# 물려받기 Frontend

단디톤 2026 · 문 닫을 대구 노포의 맛과 단골을 청년이 이어받는 모바일 웹앱

## 실행

```bash
npm install
npm run dev     # 개발 서버
npm run build   # 타입 체크 + 빌드
npm run test:api # 실서버 호출 없이 API 요청·인증·오류 검증
```

스택: React 19 · Vite · TypeScript · React Router

## 화면 확인

로그인 → 역할 선택 → 기본 정보·역할별 조건 입력 → 홈으로 이동합니다. 사장님은 가게 업종·판매 금액 등을, 청년은 자금·대출 계획·희망 조건 등을 미리 입력합니다. 사람 찾기·제안은 홈에 들어온 뒤 시작하며, 사장님의 제안을 청년이 수락한 뒤 교육·진행 과정을 확인합니다.

| 경로 | 화면 |
| --- | --- |
| `/dev/tools` | 개발용 주요 기능 테스트·계정 전환·서버 상태·선행 조건 |
| `/onboarding/profile` | 이름·나이·선택 연락처 입력 후 역할별 등록 |
| `/home` | 역할별 홈·추천 가게·서비스 소개 |
| `/shops` | 서버 추천 가게의 검색·업종 필터 / 사장님 본인 가게 |
| `/shops/:id` | 실제 가게 정보·적합도·받은 제안의 조건 |
| `/matching` | 역할별 조건 설정·가게/청년 찾기 |
| `/education` | 보낸/받은 제안·수락 후 승계 과정 |
| `/my`, `/my/profile` | 내 정보·가게 정보·매칭 조건 관리 |
| `/my/terms`, `/my/privacy`, `/my/about` | 이용약관 준비 안내·개인정보 안내·서비스 소개 |
| `/owner/shop` | 사장님·가게 정보, 업종·위치·사진 |
| `/owner/terms` | 인수 금액·포함 항목·수습 기간·근무 조건 |
| `/owner/register` | 은퇴 희망일 선택 |
| `/successor/register` | 청년 경력·자금·희망 조건 |
| `/owner/matches` | 청년 매칭·제안 진입 |
| `/offers/current` | 받은 제안 / 사장님 제안 확인 |
| `/succession/home` | 승계 홈 (할 일·단계 승인·메뉴) |
| `/succession/schedule` | 승계 가일정 |
| `/succession/checklist` | 체크리스트 |
| `/succession/plan` | AI 승계 계획 |
| `/succession/roadmap` | 수습 로드맵 |
| `/succession/payments` | 납입 관리 |

가게·청년 등록, 추천·매칭, 제안·승계 진행 화면은 `.env`의 `VITE_API_URL` 서버 API로 동작합니다. 개발 서버는 CORS 설정에 맞춰 `http://localhost:5173`을 사용하며, 포트가 사용 중이면 다른 포트로 자동 변경하지 않습니다.

카카오 시작 주소와 `/oauth/callback#token=...` 처리를 연결했습니다. 현재 배포 서버의 카카오 시작 주소가 404이므로 실제 카카오 인증에는 백엔드의 `kakao` 프로필과 앱 키 설정이 필요합니다. 휴대폰 로그인 버튼은 사용자 요청대로 비활성화했습니다. 개발 서버에서는 작은 `개발용으로 확인하기` 버튼으로 문서의 이름·역할 기반 로그인을 사용할 수 있습니다. [카카오 설정과 온보딩 흐름](docs/auth-setup.md)을 참고하세요.

제공된 API의 범위에 따른 제한입니다.

- 가게 사진: 업로드 API가 없어 현재 브라우저에서만 미리 봅니다. 공통 사진은 CC0 분위기 참고 자료입니다.
- 청년의 가게 탐색: `GET /api/youth/matches`가 반환한 추천 가게 최대 20곳 안에서 검색합니다. 전체 노포 목록·가게 역사·메뉴 가격 API는 없습니다. 사장님에게는 본인 가게를 표시합니다.
- 연락처·이메일·사장님 나이: 계정별로 현재 브라우저 탭에 보관합니다. 청년 나이는 프로필 API에 저장하며, 이름은 서버 로그인 정보를 사용합니다.
- 승계 계획: 항목 수정·동의·수정 이력을 서버에 저장합니다. 대화 전송 API가 없어 브라우저 전용 가짜 대화 기능은 제거했습니다.
- 수습 과정: 청년의 완료 요청 → 사장님의 승인 또는 다시 해 보기 요청을 각자의 로그인으로 처리합니다. 상대방 대신 처리하는 테스트 기능은 제거했습니다.

최신 명세는 [docs/openapi.json](docs/openapi.json), 구현 범위와 확인 방법은 [docs/integration-status.md](docs/integration-status.md)에 있습니다. 이전 소스 분석은 [docs/backend-contract.md](docs/backend-contract.md)를 참고하세요.

## 주요 기능 테스트

개발 서버 로그인 화면의 **주요 기능 테스트**를 누릅니다. 이미 들어와 있다면 화면 상단의 **주요 기능 테스트 · 역할 전환**이나 내 정보에서 열 수 있습니다. 역할별 이름으로 계정을 바꾸고 실제 서버의 진행 상태, 바로 열 수 있는 화면, 먼저 해야 할 일을 확인합니다.

제안 수락 → 양쪽 체크리스트 확인 → 계획 생성·양쪽 동의 → 수습 3단계·9개 일의 요청/승인 → 납입 기록/수령 확인 순서입니다. 등록만 마친 계정에는 아직 로드맵이 없습니다. 계정 전환이나 테스트 화면 조회가 단계를 자동 완료하지 않으며, 저장·수락·승인은 각 화면에서 직접 누릅니다. [역할별 테스트 순서](docs/feature-testing.md)를 참고하세요.

가게 분위기 사진은 CC0 공개 사진을 로컬 파일로 제공합니다. [사진 출처와 사용 조건](docs/image-credits.md)을 참고하세요.
