# 로그인과 온보딩 연결

수정일: 2026-11-08. 카카오·휴대폰 버튼을 임의로 이름 로그인으로 대체했던 화면을 복구했다. 휴대폰 버튼은 사용자의 후속 지시에 따라 표시만 하고 누를 수 없게 한다.

## 카카오

1. 카카오 버튼에서 백엔드 `/oauth2/authorization/kakao`의 시작 응답을 확인한다. 꺼진 서버의 404는 앱 안에서 안내한다.
2. 정상적인 리디렉션이 있으면 같은 백엔드 시작 주소로 브라우저를 이동한다. 카카오 클라이언트 키는 프런트에 넣지 않는다.
3. 백엔드가 `{FRONTEND_URL}/oauth/callback#token=...`으로 돌아오면 주소창에서 토큰을 지우고, 해당 토큰으로 `GET /api/me`를 확인한 뒤 세션에 보관한다.
4. 역할이 없는 계정은 역할 선택으로 보내고 `PUT /api/me/role`을 사용한다. 카카오로 확인된 계정을 이름 기반 개발 로그인으로 바꾸지 않는다.
5. 최초 등록·기본 정보 미완료는 기본 정보와 역할별 등록으로, 이미 등록을 마친 정상 재로그인은 홈으로 이동한다.

빈 콜백·인증 실패·사용할 수 없는 토큰은 로그인 오류를 표시한다. 토큰을 화면이나 로그에 출력하지 않는다.

## 배포 서버에서 필요한 설정

현재 시작 주소는 404를 반환하며 카카오 인증을 시작하지 않는다. 프런트 코드는 준비되어 있지만 배포 서버 설정이 켜져야 실제 카카오 로그인이 가능하다. 백엔드에는 다음 설정이 필요하다.

- Spring의 `kakao` 프로필 활성화
- `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET`
- `FRONTEND_URL=http://localhost:5173` — 이 로컬 확인본으로 돌아올 때의 주소
- 프런트 출처를 포함한 `CORS_ORIGINS`
- 카카오 개발자 콘솔의 Redirect URI: `{배포 서버 주소}/login/oauth2/code/kakao`

실제 배포 환경 값은 프런트에서 조회하거나 임의로 변경하지 않았다. 설정 방법의 근거는 백엔드 [application-kakao.yml](https://github.com/donghyun-03/mullyeobatgi-backend/blob/main/src/main/resources/application-kakao.yml), [SecurityConfig.java](https://github.com/donghyun-03/mullyeobatgi-backend/blob/main/src/main/java/com/danditon/mullyeobatgi/auth/SecurityConfig.java), [KakaoLoginSuccessHandler.java](https://github.com/donghyun-03/mullyeobatgi-backend/blob/main/src/main/java/com/danditon/mullyeobatgi/auth/KakaoLoginSuccessHandler.java)다.

## 온보딩

역할 선택 등으로 온보딩에 명시적으로 들어온 경우에는 기존 등록 여부만으로 입력 단계를 건너뛰지 않는다.

- 사장님: 기본 정보 → 저장된 가게 정보 확인·수정 → 물려줄 조건 → 은퇴 희망일 → 저장 후 홈
- 청년: 기본 정보 → 저장된 경력·자금·희망 조건 확인·수정 → 저장 후 홈
- 저장된 값은 다시 불러오며 조회 실패 시 기본값으로 덮어쓰지 않는다.
- 카카오 계정의 이름은 서버의 이름을 읽기 전용으로 사용한다.

개발용 이름 로그인은 `POST /api/auth/dev-login`이다. 전화번호를 이름으로 전달해 휴대폰 인증인 것처럼 처리하지 않으며, 휴대폰 인증 API를 임의로 만들지 않는다.

## 두 역할 시연하기

개발 서버의 `개발용으로 확인하기`에서만 역할을 자유롭게 바꾼다. 등록한 실제 계정의 역할을 변경하는 대신, 선택한 역할의 개발용 계정으로 로그인한다. 기본 계정은 사장님 `김순자`, 청년 `이도윤`이며, 기본 정보에서 이름을 바꾸면 해당 이름의 개발용 계정을 사용한다.

- 기본 정보 화면에서 뒤로 → 다른 역할 → 다음으로 전환한다.
- 홈에 들어간 뒤에는 내 정보 → `다른 역할로 확인하기`를 누른다.
- 제안부터 수습·납입까지 이어서 보려면 로그인 또는 내 정보의 `주요 기능 테스트`를 연다. 각 화면 상단에서도 돌아갈 수 있으며 [역할별 확인 순서](feature-testing.md)를 따른다.
- 역할마다 마지막 시연 이름을 기억하고 계정별 저장 정보를 불러온다. 다른 계정의 입력 초안·사진·선택한 청년은 전환 시 비운다.
- 새로고침해도 현재 탭의 개발용 확인 상태는 유지한다. 로그아웃하거나 카카오 인증을 마치면 해제한다.
- 전환 실패 시 기존 계정은 유지하며 오류를 표시한다. 전환 자체가 가게 저장·제안·수락을 실행하지 않는다.

카카오 계정의 등록 후 역할 잠금은 유지한다. 운영 빌드는 개발용 진입과 모드 복원·개발 로그인 호출을 허용하지 않는다.
